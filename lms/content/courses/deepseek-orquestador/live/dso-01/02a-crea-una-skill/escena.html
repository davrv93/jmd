Skill = instrucciones reutilizables

Una skill existe solo si DSH la descubre

El nombre de carpeta, el archivo SKILL.md y el YAML deben coincidir. Un front matter inválido puede hacer que desaparezca del catálogo sin aviso.

1 · Elige dónde vive

1

<repo>/.dsh/skills/mi-skill/SKILL.md
Primera prioridad dentro del proyecto.

2

<repo>/.agents/skills/mi-skill/SKILL.md
Compatible con otros agentes.

3

~/.dsh/skills/mi-skill/SKILL.md
Disponible para tus proyectos.

2 · Escribe el archivo mínimo

---
name: revisar-api
description: "Revisa una API: contrato, errores y evidencia. Úsala cuando pidan validar un endpoint."
---

# Revisar una API
1. Lee el contrato.
2. Ejecuta casos válidos e inválidos.
3. Entrega evidencia.

La trampa del YAML

Si el texto contiene : , pon toda la descripción entre comillas. El name debe estar en kebab-case y coincidir con el nombre que invocarás: revisar-api.

Pedido copiable

Crea, valida y carga la skill

Crea una skill de proyecto llamada revisar-api en .dsh/skills/revisar-api/SKILL.md. Usa front matter YAML válido con name y description entre comillas cuando corresponda. Su flujo debe leer el contrato, probar casos válidos e inválidos y entregar evidencia. Después confirma que revisar-api aparece en el catálogo de skills de esta sesión, cárgala con la herramienta skill y resume la primera instrucción que cargaste. Si no aparece, revisa el YAML y la ubicación; no afirmes que cargó sin comprobarlo.

Prueba de carga: aparece en el catálogo → DSH llama skill({ name: "revisar-api" }) → devuelve el cuerpo de SKILL.md.
