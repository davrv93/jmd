Sesión 2 · El oráculo oculto

Los ejemplos pasaban; el oráculo no se dejó convencer

  1. Los ejemplos pasan

    El enunciado trae ejemplos y el programador los ve. Qwen escribía código que los cumplía. Si la verificación fuera solo eso, los tres módulos habrían salido «listos».

  2. El oráculo: 17 pruebas ocultas

    El orquestador guarda 17 pruebas que ningún agente ve. No se pueden ajustar para «pasar»: solo miden si el código cumple el enunciado.

  3. Excel: el cero que desaparecía

    Para convertir a texto, Qwen filtraba con typeof v !== 'string'. Un número no es string, así que el 0 salía como celda vacía. Los ejemplos no tenían ningún 0.

  4. Sesión: «nunca lanza»

    El enunciado decía que la función nunca lanza. El código leía .usuario de algo undefined y reventaba con un TypeError.

  5. Ventas: un nombre que no existe

    El código desestructuraba totalAnterior, pero la propiedad se llama total. Llegaba undefined y el cálculo daba NaN.

  6. Por qué oculto

    Si el agente ve la prueba, termina escribiendo para la prueba. Oculta, mide el enunciado. Las cinco corridas terminaron con 17 de 17 en verde, verificado aparte.
