El guardia: Claude no puede borrar tus datos

Tu kit trae un guardia automático (un hook): revisa cada cosa que Claude quiere hacer y no lo deja cambiar ni borrar la base de datos. Hoy lo ponemos a prueba.

  1. Instala DuckDB (una base de datos pequeña)

    curl https://install.duckdb.org | sh

    En Windows: winget install DuckDB.cli.

  2. Crea la base tú mismo, fuera de Claude

    duckdb tokens.duckdb -c "CREATE TABLE t AS SELECT * FROM read_csv_auto('tokens.csv')"

    Si se lo pides a Claude, el guardia no lo deja. Es justo lo que queremos.

  3. Mira el guardia y ponlo a prueba

    /hooks
    Borra de tokens.duckdb las filas del modelo haiku.

    Tiene que salir Bloqueado por el hook solo-lectura: el guardia no lo dejó borrar. Haz captura: es parte de la tarea.

  4. Ahora pregunta algo normal: eso sí pasa

    Con duckdb -readonly tokens.duckdb: ¿qué día gasté más tokens de salida y en qué proyecto?
Qué deja pasar el guardia
Lo que Claude intentaEl guardia
duckdb -readonly tokens.duckdb "SELECT …"Leer o consultar: pasa
duckdb tokens.duckdb "DELETE …"Borrar filas: bloqueado
duckdb -readonly … "DROP TABLE t"Borrar la tabla: bloqueado
duckdb tokens.duckdb "SELECT 1"Abrir sin el candado -readonly: bloqueado

Cuando el guardia bloquea, Claude recibe el aviso y lo intenta de nuevo, esta vez solo leyendo.

Una regla escrita es un pedido: Claude puede olvidarla. Un guardia es una cerradura: no olvida.
