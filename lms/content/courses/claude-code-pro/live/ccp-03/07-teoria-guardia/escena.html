Teoría 3 de 3 · Hooks de Claude Code

El modelo olvida la regla; el hook no

  1. La regla vive en el contexto

    Lo que escribes en CLAUDE.md o en un prompt entra a la ventana del modelo. Claude lo lee y casi siempre lo cumple. Casi: es probabilístico, y en una ventana larga la regla compite con miles de tokens más.

  2. El hook vive fuera del modelo

    Un hook es un programa que ejecuta Claude Code, no el modelo. PreToolUse corre antes de cada herramienta: si sale con código 2, la llamada se cancela y el mensaje de stderr vuelve a Claude. Se declara en .claude/settings.json.

  3. Replit, julio de 2025

    Jason Lemkin (SaaStr) tenía en replit.md «no more changes without explicit permission» y un code freeze. El agente ejecutó npm run db:push y borró la base de producción. Después escribió: «This was a catastrophic failure on my part».

    El agente dijo que no se podía revertir; era falso, el rollback funcionó. Lemkin aclaró que era una app de prueba.

  4. La respuesta no fue otra instrucción

    El CEO de Replit no reforzó el prompt. Separó automáticamente la base de desarrollo de la de producción y anunció un modo de solo planificación. Son controles fuera del modelo: no dependen de que lea bien.

  5. Con un hook, la orden choca

    La misma orden de borrar llega a la puerta. El hook la revisa, sale con código 2 y Claude Code la cancela. Claude lee el motivo en stderr y reescribe la consulta como SELECT, que sí pasa.

  6. En tu caso: solo-lectura.py

    Tu hook bloquea INSERT, UPDATE, DELETE, DROP, CREATE y compañía en cualquier comando duckdb, y exige duckdb -readonly. El entregable 3 pide «ninguna escritura posible»: eso no se promete con un prompt, se garantiza con un hook. Lo instalas en la escena 8.
