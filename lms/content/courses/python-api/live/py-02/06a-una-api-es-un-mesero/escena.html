Teoría 4 de 4 · FastAPI, Pydantic y Swagger

Una API es un mesero que habla HTTP

  1. Un pedido, una respuesta

    Una API es un mesero: el cliente pide con un método y una ruta, GET /productos/2, y recibe un código y un JSON: 200 y el producto. El cliente puede ser una web, una app o Excel.

  2. Cuatro verbos para un inventario

    POST crea, GET lee, PUT edita y DELETE borra: el CRUD. Cada respuesta trae un código: 201 creado, 200 bien, 204 borrado sin contenido y 404 si el id no existe.

  3. El decorador conecta la ruta

    @app.get("/productos/{id}") une esa ruta con tu función. El «2» de la URL llega como texto; id: int lo convierte en número, y si mandan «abc», FastAPI responde 422 por ti.

  4. Pydantic revisa la comanda

    Un modelo dice cómo debe venir un producto: nombre texto, precio mayor que 0, stock entero. Si llega precio −3, FastAPI responde 422 y dice qué campo falló, sin que escribas un solo if.

  5. Swagger se escribe solo

    Con tus tipos y decoradores, FastAPI arma la especificación OpenAPI y la página /docs. Ahí pruebas cada ruta con «Try it out», sin Postman ni código extra.

  6. Tu API, en minutos

    Instalas FastAPI, escribes main.py con cinco rutas y un modelo, y abres /docs. Es lo que haces ahora, en la escena siguiente.
