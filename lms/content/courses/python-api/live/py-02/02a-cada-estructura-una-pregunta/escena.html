Teoría 1 de 4 · Estructuras de datos de Python

Cada estructura responde una pregunta

  1. list: ¿en qué orden?

    Una lista guarda cosas en fila, en el orden en que llegan. Admite repetidos y se puede cambiar: append agrega al final. Le preguntas por posición: pedidos[0] es el primero.

  2. tuple: ¿qué no debe cambiar?

    Una tupla también va en orden, pero queda fija: si intentas cambiarla, Python responde TypeError. Sirve para datos que van juntos y no se tocan, como las coordenadas de tu tienda.

  3. dict: ¿cuánto hay de…?

    Un diccionario une una clave con su valor. No buscas por posición sino por nombre: stock["arroz"] responde 12 sin revisar lo demás. Las claves no se repiten.

  4. set: ¿ya está?

    Un conjunto guarda cada cosa una sola vez y sin orden. Si agregas «abarrotes» dos veces, queda uno. Sirve para quitar repetidos y para preguntar si algo ya existe.

  5. Tu inventario: una lista de dicts

    Combinadas responden todo: la lista da el orden y cada dict, los campos de un producto. Eso mismo, en JSON, es lo que hoy devolverá tu API en GET /productos.
