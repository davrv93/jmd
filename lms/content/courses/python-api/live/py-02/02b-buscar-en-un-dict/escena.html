Teoría 2 de 4 · Tablas hash

Buscar en una lista es preguntarle a cada uno

  1. La lista revisa uno por uno

    Para saber si «Z99» está en una lista, Python la compara elemento por elemento, desde el primero. Si está al final, o no está, revisa todos: con un millón de códigos, un millón de comparaciones.

  2. El set calcula dónde buscar

    Un set o un dict pasa la clave por hash(), que la convierte en un número, y ese número dice en qué casilla está. Va directo: un paso, tenga mil o un millón.

    Simplificado: Python usa tablas más grandes y resuelve cuando dos claves caen en la misma casilla.

  3. Medido: unas 240 000 veces

    Con timeit, buscar el último de un millón tarda 3,2 ms en la lista y 13 nanosegundos en el set. Una búsqueda no se nota; mil por segundo en tu API, sí.

  4. Por eso la clave no puede cambiar

    Si una clave cambiara, su número de casilla ya no serviría. Por eso Python solo acepta claves fijas: una tupla sí, una lista no.

  5. Tu API busca por id en un dict

    Guarda los productos en un dict cuya clave es el id. GET /productos/2 será productos[2]: directo, sin recorrer todo el inventario.
