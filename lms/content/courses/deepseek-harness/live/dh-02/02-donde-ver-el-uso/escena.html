Entrada = acierto + fallo, igual que en Usage. Las cifras de ejemplo son las de la tabla de la primera pestaña. aula dsh a secas abre el modo dsh>: cada línea es una tarea y, al salir, ves el USO DE LA SESIÓN sumado. CPU/RAM no salen aquí: el resumen solo cuenta tokens, llamadas y tiempo.

# la clave para el perfil headless (no lee la guardada en Settings)
read -s DEEPSEEK_API_KEY && export DEEPSEEK_API_KEY
# correr, medir el tiempo y guardar los eventos
time npx @deepseek-ai/dsh --profile headless --json "TAREA" > docs/medicion/A.jsonl
# sumar el uso que informa el proveedor, paso a paso
jq -s '[.[]|select(.type=="status" and .phase=="step_end" and .usage)|.usage]|{llamadas:length,entrada_fallo:(map(.inputTokens//0)|add//0),entrada_acierto:(map(.cacheReadTokens//0)|add//0),salida:(map(.outputTokens//0)|add//0)}' docs/medicion/A.jsonl

Cada paso trae inputTokens (solo la entrada que no vino de caché), cacheReadTokens (acierto) y outputTokens. Entrada facturable = fallo + acierto. Si un paso no informa uso, no se suma: avísalo en tu ficha.

# macOS: tiempo y memoria máxima del proceso (salida REAL de esta Mac, Node 24.2.0, foto de dist/muebleria)
$ /usr/bin/time -l node skills/foto-del-sistema/motor/foto.mjs . --silencio
        0.15 real         0.20 user         0.02 sys
            91930624  maximum resident set size   # bytes en macOS ≈ 92 MB

# Linux: lo mismo con -v (campos «Elapsed» y «Maximum resident set size (kbytes)»)
$ /usr/bin/time -v node skills/foto-del-sistema/motor/foto.mjs .

En el Monitor de actividad (macOS) o en htop (Linux) mira las columnas CPU y Memoria del proceso node mientras corre el agente. Tomar la foto cuesta 0 tokens: es un script, no un modelo.
