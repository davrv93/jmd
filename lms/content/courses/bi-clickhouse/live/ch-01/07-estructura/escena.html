Estructura: hechos y catálogos

La tabla de hechos guarda cada venta. Los catálogos guardan el nombre oficial de cada sede y categoría.

Catálogos: el nombre oficial
CREATE TABLE dim_sede (sede LowCardinality(String))
ENGINE = MergeTree ORDER BY sede;
INSERT INTO dim_sede VALUES ('Arequipa'),('Lima Centro'),('Miraflores'),('Surco');

CREATE TABLE dim_categoria (categoria LowCardinality(String))
ENGINE = MergeTree ORDER BY categoria;
INSERT INTO dim_categoria VALUES ('Bebés'),('Cuidado personal'),
  ('Dermocosmética'),('Medicamentos'),('Suplementos');
Tabla de hechos con sus tipos
CREATE TABLE ventas (
  fecha     Date,
  sede      LowCardinality(String),
  categoria LowCardinality(String),
  unidades  UInt32,
  venta     Decimal(12, 2),
  margen    Nullable(Decimal(5, 3))
) ENGINE = MergeTree ORDER BY (fecha, sede, categoria);
Pasar de crudo a limpio
INSERT INTO ventas
SELECT DISTINCT
  toDate(parseDateTimeBestEffortOrNull(trim(c.fecha))) AS fecha,
  s.sede,
  k.categoria,
  toUInt32(trim(c.unidades)),
  toDecimal64(trim(c.venta), 2),
  toDecimal32OrNull(trim(c.margen), 3)
FROM ventas_crudo AS c
INNER JOIN dim_sede AS s ON lowerUTF8(trim(c.sede)) = lowerUTF8(s.sede)
INNER JOIN dim_categoria AS k ON lowerUTF8(trim(c.categoria)) = lowerUTF8(k.categoria);
¿Por qué estos tipos?

Date para poder agrupar por mes. Decimal para dinero: con decimales flotantes, S/ 0,10 + S/ 0,20 no da exacto. LowCardinality para textos que se repiten mucho, como la sede.

El catálogo también te avisa: una sede escrita de una forma nueva no cruza con el catálogo, y al contar filas lo ves.
