Cómo se produce · la herramienta pone las cifras, tú pones el juicio
npm test → informe/datos.json (tu redacción) → npm run informe → npm run informe:revisar → .docx

Las tablas (casos, resultados, defectos, cobertura) salen de la corrida. Objetivo, alcance, criterio de salida, riesgos, conclusión y recomendación los escribes tú. Sin eso el Word sale con huecos amarillos.

Criterio de salida · se acuerda ANTES de correr, no después de ver el rojo

Alta en rojo → NO APTO. Solo Media o Baja en rojo → APTO con observaciones (responsable y fecha). Todo verde con pendientes → APTO con riesgo (se declara qué no se probó). Todo verde y nada pendiente → APTO.

El veredicto se argumenta con IDs y cifras: «3 de 23 fallan: DEF-01 a DEF-03, todos Alta, en la pantalla de venta; la API pasa entera». Un «todo bien» sin números no es un informe.

Un verde en la terminal se olvida al cerrar la ventana; el informe es lo que el equipo lee, firma y guarda
